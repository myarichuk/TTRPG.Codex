## 3. Licensing: SRD / ORC

### 3.1 What the repository actually contains

Grepping every `*.cs`, `*.razor`, `*.yaml`, `*.json`, `*.md` under `src/` for spell, class, feat, or monster
names finds **no game content at all**. The only rules-adjacent strings are the six ability-score names, the
nine alignment abbreviations and the eight schools of magic in `DnD5ePlugin.GetUISchemas()`. All three lists
appear in SRD 5.1 §"Using Ability Scores", §"Alignment" and §"Spellcasting" and are CC-BY-4.0; they are
also generic enough to be uncopyrightable as such. **Nothing has to be deleted on licence grounds.**

### 3.2 What is wrong anyway

- `src/Codex.Systems.DnD5e/LEGAL.md` states "This work includes material taken from the System Reference
  Document 5.1" and "Spell data is sourced from vorpalhex/srd_spells". Neither is true: no SRD text and no
  spell data exist in the tree. An attribution for absent content is misleading in the other direction.
- The system is named **"DnD5e"** / **"D&D 5E"** in `SystemId`, badges, filter chips and boot messages.
  CC-BY-4.0 on the SRD grants no trademark rights; the SRD legal page permits only the phrases
  *"compatible with fifth edition"* or *"5E compatible"* and asks that no other attribution to Wizards be
  added (SRD 5.2.1 p.1). The product name must not be used as a system label.
- There is no place in the UI where a CC-BY attribution could be displayed even if content were added.

### 3.4 Attribution text that must be displayed

For SRD 5.2.1, verbatim from the document's Legal Information page:

> This work includes material from the System Reference Document 5.2.1 (“SRD 5.2.1”) by Wizards of the Coast LLC,
> available at https://www.dndbeyond.com/srd. The SRD 5.2.1 is licensed under the Creative Commons Attribution 4.0
> International License, available at https://creativecommons.org/licenses/by/4.0/legalcode.

CC-BY-4.0 §3(a)(1)(B) additionally requires indicating that the material was modified (it was: restructured
into YAML, descriptions trimmed of layout artefacts). The 5e-bits MIT notice must accompany the converted data.

## 4. Actions taken in this pass

Filled in as the work landed; see the commit for the diff.

### Licensing
- Removed the inaccurate `LEGAL.md`; added a root `LEGAL.md` and a per-pack `manifest.yaml` `license:` block
  carrying the verbatim SRD 5.2.1 statement, the modification notice, and the 5e-bits MIT notice.
- Renamed the system from `DnD5e`/"D&D 5E" to id `srd5e`, display name **"Fifth Edition SRD (5.2.1)"**, with
  "5E compatible" as the only product reference, per the SRD legal page.
- Added an **About & licences** page (`/about`) that lists every loaded system and pack with its attribution,
  and an attribution footer on every content entry's detail view, so CC-BY attribution is shown wherever the
  material is used.
- Removed the "Loading D&D 5E Plugin..." / "FFG Force Dice" boot copy.

### Data-driven systems and content (F9, F11)
- Systems are now **YAML** (`content/systems/<id>/system.yaml`): attributes, resources, actor sheet fields,
  entity types with field schemas, conditions, dice conventions, licence. `DataDrivenSystemPlugin` turns one
  into an `ICodexSystemPlugin`; compiled plugins are still supported for code-level extensions (custom dice).
- Content packs gained a generic `ContentEntry` (`type`, `id`, `name`, `description`, `tags`, `properties`,
  `inherits`) loaded from `<pack>/<type>/*.yaml`; `abilities/`, `actors/`, `locations/` keep working.
  Entry types flagged `actorBlueprint: true` in the system (monsters) are also registered as actor blueprints.
- `tools/Codex.ContentImport` converts the 5e-bits 2024 JSON into the pack format; the generated pack is
  committed at `content/systems/srd5e/packs/srd-5.2.1/`.
- Example homebrew system (`content/examples/simple-d6`) and world pack (`content/examples/homebrew-world`)
  demonstrate the format and double as test fixtures.
- Deleted `src/Codex.Systems.DnD5e` (replaced by `system.yaml`) and `src/Codex.Authoring` + `conductor/`
  (F10); `ContentPackExporter` moved to `Codex.Core` and now exports homebrew as a pack from the web UI.

### Homebrew and campaign content (F9)
- `HomebrewEntryDocument` + repository: DM-authored entries scoped to a campaign, merged into the campaign's
  Library search, included in campaign export/import, exportable as a standalone pack.
- `CampaignDocument.ActivePacks` is honoured: campaign settings pick which packs are in play.

### UI (F1–F8, F13–F15, U1–U13)
- One campaign list (`/`), one campaign workspace with **routed** sections
  (`/campaigns/{id}/{overview|cast|world|lore|sessions|table|library|settings}`), `CampaignDetail` split
  into one component per section.
- New-campaign dialog (name, system, description); players can create their own character; schema-driven
  sheet with content pickers (class/species/background) backed by the Library.
- Removed `Players`, global `Grimoire`, "Oracle", dead search boxes, Unsplash, Gravatar, ui-avatars, CDN
  scripts and fonts; Bootstrap CSS is vendored, icons are inline SVG, fonts are the system stack.
- Accessibility: every control labelled, routed sections use `aria-current`, flash messages are
  `role="status"`, `<dialog>`-based confirm, light/dark theme following `prefers-color-scheme` with a toggle,
  `prefers-reduced-motion` honoured, tertiary text raised to ≥4.5:1.
- Plain-language copy (Sign in, Password, Delete campaign…).

### Tests
- Unit: system definition loading/validation, data-driven plugin schemas, generic registry + search,
  pack loader (manifest.yaml, typed folders, licence), importer mapping, SRD pack smoke test
  (counts and attribution), homebrew repository authorisation, formatter escaping.
- Playwright: campaign lifecycle via the dialog; Library browse/search/detail with attribution; DM homebrew
  visible to players; player self-created character with SRD pickers; accessibility smoke (no unlabelled
  controls, keyboard-only campaign creation). Phase 3/4 scenarios updated to the new routes.

### Found along the way
- Razor compiles an unknown component tag as plain HTML without an error; a dropped `@using` in
  `_Imports.razor` turned `<AuthorizeRouteView>` into a redirect loop during this work. The web
  project now treats RZ10012 (unknown component) as a build error.
- `LocationEdge` and `FieldDefinition` were positional records, which YAML could not deserialise;
  both are plain classes now so packs can describe them.
- `aria-pressed` bound to a bool rendered as an empty attribute; chips now emit "true"/"false".

### Left alone, on purpose
- OAuth providers, RavenDB persistence layer, the ECS runtime and command loop (reviewed, no defects found
  beyond F14).
- F14's "players don't see the table start" needs a campaign-level broadcast; a `TableStarted` event is now
  raised by `CampaignRuntimeManager`, and the table page subscribes, but idle eviction still has no timer.
- Pathfinder 2E content: not shippable legally (see §3.3).
