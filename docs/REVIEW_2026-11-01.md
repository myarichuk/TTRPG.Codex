# TTRPG.Codex — Code and UX review of 2026-11-01

*Review of `main` @ `9777a54`. Method: a full read of every project (web, persistence, core, abstractions,
launcher, content loading, tests) split across six area reads plus a cross-cutting pass; every finding below
was verified against the code at the quoted line, not inferred from names. `dotnet build -c Release`: 0 errors,
10 warnings (nullable, tests only). `dotnet test` without the `E2E` namespace: 1012/1013 pass; the one failure
(`TemplateGrammarTests.TheEditorsParser_ReadsEveryCaseAsTheServerDoes`) launches Playwright and only fails
for lack of a browser binary, so it is an environment matter, but see T1.*

*The yardstick for UX is Owlcat's Pathfinder games: every term is a link to an explanation shown as a card you
can pin and chain; the big screens (sheet, inventory, journal) are windows over the play area and closing one
puts you back exactly where you were; dense, scannable stat blocks with portraits and condition icons; a hover
breakdown of every number; consequences spelled out before you commit; undo for mistakes.*

Severity: **P0** secret leak / data loss / broken core feature; **P1** wrong behaviour users will hit;
**P2** edge cases and real friction; **P3** maintainability.

---

## 0. Verdict in one paragraph

The architecture is sound and most of what the last two remediation rounds promised has landed: server-side
redaction behind `CampaignAccess`, the single-writer runtime loop, `RavenUpdate` for shared documents, the
fence around campaign text in AI tool results, the secret-block check on AI edits. The bugs that remain are
of three kinds. First, **seams between subsystems that each assume the other one did the checking**: the
sheet's long-text fields never meet `SecretText`, the combat console trusts the runtime to hide actors but
renders counts and rolls from the full list, the mention encoder trusts names when the stored text had ids.
Second, **whole-document writes that still exist** (wiki pages, actors without a live table, users) after a
plan that said to remove them. Third, **UX that stops at the page boundary**: nothing opens as a window, the
hover card is a tooltip and only on desktop, there is no undo anywhere, and a lost SignalR circuit reloads the
page and discards whatever was typed. There is also one plain breakage: external sign-in (Google, Apple)
throws on every real callback and only the hand-built test ticket hides it.

## 1. Secrets reaching players (P0)

**S1. `:::dm` blocks in sheet long-text fields are shown to every player.**
`RavenActorRepository.Redact` (`src/Codex.Persistence/RavenActorRepository.cs:41-69`) strips secrets from
`Biography`, `DmNotes` and `PublicDescription` only. Every `LongText` sheet field (the SRD `notes`,
backstory-style fields) is rendered raw by `SchemaForm.razor:139-142` for whoever can open the sheet. The
product teaches the syntax as working in "a character's history" (`SecretText.cs:56-58`,
`Campaign.Wiki.SecretHint`) and nothing says the sheet's Notes box is the exception. Scenario: DM writes
`:::dm Secretly a doppelganger :::` in a Known NPC's Notes; every player reads it.
Fix: run `SecretText.ForPlayers` over `LongText` fields in `Redact` (and `KeepSecrets` on a player save), or
render them through `MarkdownEditor`/`SecretRender` with the `Secrets` flag.

**S2. Hidden combatants are announced by the roll log and the turn counter.**
`CombatConsole.razor:80` renders `L["Combat.TurnOfCount", TurnIndex+1, Participants.Count]` from the
unfiltered participant list: a player sees four rows and "Turn 3 of 7". `VisibleRollLog` (`:1090-1094`)
filters only `IsSecret`; `ResolveRollerName` (`:1097-1100`) prints "Someone you can't see" but `DiceResult`
still shows `1d20+2 … 16`. Quick-added monsters default to `Visibility = Hidden` (`:1056`), so the planned
ambush is announced, with initiative, the moment the DM rolls for it. The comment at `:96-99` states the
opposite intent.
Fix: for non-DM viewers drop roll entries whose `ActorId` is not in the visible set (or auto-mark rolls of
Hidden actors `IsSecret`); compute "of N" over visible participants or omit it for players.

**S3. A `:::for` reveal silently moves to a same-named character on any later save** (remediation 1.4, not
landed). `SessionMentions.ForEditing` (`src/Codex.Persistence/SessionMentions.cs:226-234`) turns every
stored `[[actor:id]]` into `@Name`, including on `:::for` opener lines; `Encode` (`:140-147`) resolves a name
to the first `_byLength` match. Two PCs named Bram: a reveal to Bram(b), then any typo fix saved by the DM,
re-encodes the opener to Bram(a). Same path in `WikiSection.razor:726/1036`, `LoreSection`,
`WorldSection.razor:439,489`. The glued form `the[[actor:id]]` also round-trips to a dead `the@Bram`
(`Encode` requires a non-letter before `@`).
Fix: leave `[[actor:id]]` untouched on marker lines in `ForEditing`; when a name is ambiguous, prefer the id
that stood at that position in the stored text, or refuse with a message; disambiguate same-name suggestions.

**S4. "Describe with AI" on a place feeds `:::dm` blocks to a Players-audience prompt and overwrites the
box.** `WorldSection.razor:509` → `Ai.DescribeAsync(…, text, …, AiAudience.Players)` with the full editor
text; `AiPrompts.Describe` (`src/Codex.Core/AI/AiPrompts.cs:312-331`) says "no secrets, no game-master
asides" and, unlike `Rewrite`/`WikiPage`, never says to keep marker lines; `AiTextField.razor:95-100` writes
the reply straight into `Value`. The model either deletes the block (secret lost on save, no `KeepSecrets` on
the DM path) or paraphrases it into the visible prose. The world-builder edit path got exactly this guard
(`SecretText.LostSecrets`); the one-click button did not.
Fix: strip secret blocks before sending and re-attach after (as `AiAssistant.WritePlayersVersionAsync` does),
or run `LostSecrets(before, after)` and refuse the draft.

**S5. Recaps and comments teach nothing about `:::` and ignore it.** `SessionDetail.razor:114` renders the
recap for players with `MentionLinks.ToHtml` (no `SecretText`); wiki/session comments (`NoteDocument`) go
through `MentionText` unredacted. A DM who pastes a paragraph from a wiki page into the recap ships the DM
block, marker lines included. Fix: redact these too (cheap and consistent), or refuse saving them with marker
lines and say why.

**S6. Smaller leaks.** A stranger's `Kind` survives `Mask` (`RavenActorRepository.cs:78-89`), so the hover
card labels a "hooded stranger" as "Monster" (`PreviewEndpoints.cs:66`). `LocationDocument.Connections` is
dead data but `RavenRegionRepository.ForPlayers` (`:51-58`) leaves it unredacted on Known places. Player
search matches `:::party 2026-…` stamp lines (`WikiSection` `Filtered` ~`:670`; remediation 1.6b). Hover
cards under "view as players" still show DM text (remediation 1.5). `SessionEventRedactor.Project` fails
*open*: an event type with no `PlayerDescription` is shown exact (`SessionEventRedactor.cs:55`); nothing
leaks today because every numeric event sets one, but the default is the wrong way round. `LogTerms.Source`
resolves `SourceId` to a real name while `ActorIds` carries only the target (`RuntimeCommands.cs:30,79`), so
any future caller that passes a hidden source leaks its name.

## 2. Broken or data-losing behaviour (P0/P1)

**D1. External sign-in throws on every real callback (P0).** `Program.cs:383`:
`authenticateResult.Properties?.Items["LoginProvider"] ?? …`. `Items` is a dictionary; the indexer throws
`KeyNotFoundException` on a missing key and `??` does not catch exceptions. The remote handlers write only
`.AuthScheme`; `LoginProvider` is an Identity `SignInManager` convention this app never uses. Google/Apple
users get the generic `/Error` page. The tests pass because `OAuthTestFixtures.cs:38` hand-builds a ticket
with `["LoginProvider"]` and never drives the endpoint.
Fix: `Items.TryGetValue(".AuthScheme", …)`, fall back to `AuthenticationType`; add a test that builds the
ticket the way `RemoteAuthenticationHandler` does.

**D2. Wiki page saves are whole-document, last-writer-wins; a reveal made meanwhile is undone (P0).**
`RavenWikiRepository.TrySaveAsync` (`WikiModels.cs:223-258`) copies `Body/Visibility/…` onto a fresh load
with no change-vector check. Reveal/hide go through `RavenUpdate` so they never clobber an edit, but an edit
clobbers a reveal (`:::party` → back to `:::dm`, or a Hide undone and the secret re-exposed). Also used by
"Share page" (`WikiSection.razor:1099`) and by the world builder's apply (`WorldBuilderService.cs:703,998,
1024,1181`). The remediation plan called for `TryReplaceAsync(expectedChangeVector)`; only
`WorldChatModels.cs` checks versions.
Fix: keep the change vector on the document given to the editor; replace under optimistic concurrency; on
conflict reload and tell the DM, keeping their text in the box.

**D3. Actor sheets: three save paths, three merge semantics (P1).**
- Without a live table, `RavenActorRepository.cs:189` `target.Sheet = source.Sheet` replaces everything with
  no concurrency check: DM fixing notes and a player adding feats between sessions overwrite each other.
- With a live table, `SheetRuleEngine.Vitals.ApplyHitPoints` (`Vitals.cs:165-174`) rewrites
  `HP = current + (newMax − oldMax)` from the HP captured at load, and `CampaignRuntime.ReplaceActor`
  (`:561-564`) keeps the live value only when edited == baseline. Opened at 30/30, dropped to 12 by the
  table, Con raised 14→16: 35 is written over 12. `TrySaveActorAsync` receives `loadedSheet` (`:1452`) while
  dirty tracking uses `baselineSheet` (`:1171`): two baselines for one save.
- The sheet's slot tracker edits `editSheet` and needs Save, the Table tab is live; "Use" on the sheet then
  Save overwrites the table's count.
Fix: optimistic concurrency with a "changed since you opened it" error (the history path at `:226-229`
already has one); merge HP by delta against live; one baseline; route sheet slot/HP buttons through runtime
commands when a table is live (as `RollAsync` already does).

**D4. Adding or removing picks is never "unsaved", so the leave guard stays silent (P1).**
`ActorSheet.razor:1010`: `if (!Equals(now, before) && now?.ToString() != before?.ToString()) count++`. Every
list field is a `List<object>`; two different lists fail `Equals` but share
`"System.Collections.Generic.List`1[System.Object]"` as `ToString()`, so the key is skipped. A player prepares
six spells, taps a breadcrumb, no dialog, edits gone. `YamlValues.SameValue` (`YamlValues.cs:108`) exists for
this. Fix: use it.

**D5. Portrait upload/remove/generate saves the whole sheet and bypasses strict enforcement (P1).**
`ActorSheet.razor:1505-1551,1577` → `ApplyEdits(actor)` → `TrySaveActorAsync` with no `Enforcement` gate
(contrast `SaveNowAsync` `:1471-1483`). A strict-mode player with "Not saved: 1 rule problem" uploads a
portrait and the violating sheet is persisted, together with any half-typed edits. Fix: patch
`HasPortrait/PortraitVersion` via `ActorRepo.UpdateAsync` only.

**D6. "End the table" promises the initiative order comes back; the UI can never bring it back (P1).**
`EndTableAsync` (`CombatConsole.razor:466-476`) → `RuntimeManager.EvictAsync` → session marked
**Completed** (`CampaignRuntimeManager.cs:298-321`). `Combat.EndTableCombat` says "The initiative order is
kept and comes back when this session's table is started again", but `LoadOpenSessionsAsync` (`:398-403`)
filters `Status != Completed`, and a new start opens a new session whose `FindOpenEncounterAsync` finds
nothing. The `EncounterDocument` is orphaned. Fix: do not complete the session while an encounter is open
(the `completeSession:false` path exists), or list the last completed session with an open encounter; fix the
string.

**D7. "Roll initiative" rolls twice and logs a number other than the one it sets (P1).**
`CombatConsole.razor:563-573` rolls on the Blazor thread, enqueues a `RollDiceCommand` whose `Apply`
(`RuntimeCommands.cs:639`) rolls *again* and logs that, then enqueues `SetInitiativeCommand` with the first
total. The log says 16, the order says 9. Untested: E2E drives only the manual Set. Fix: one command that
rolls inside `Apply`, records the roll and sets initiative from the same result.

**D8. A console click that throws kills the DM's circuit (P1).** Every handler is `runtime!.EnqueueAsync(…)`
with no `try/catch` except `RollDiceAsync` (`:1077-1088`, `FormatException` only); the loop rethrows into the
caller (`CampaignRuntime.cs:478-482`); there is no `<ErrorBoundary>` anywhere in `src/Codex.Web`. A RavenDB
hiccup in `PersistDirtyAsync` on "Next turn", or `Detach()` after idle eviction nulling `runtime` mid-click,
ends the table page. `DiceExpressionParser` uses `int.Parse` (`:50-55,81`): `1d20+99999999999` throws
`OverflowException`, not `FormatException`, and the parser's contract (`IDiceRoller.cs`) names only the
latter. Fix: one `SendAsync` helper that catches and flashes `L.Describe(ex)`; `TryParse` → `FormatException`;
wrap `@Body` in an `ErrorBoundary`.

**D9. A failed or expired circuit reloads the page and discards everything typed (P1).**
`app-startup.js:33-35` `location.reload()` on `rejected`; `:43-46,53-57` reload when `resumeCircuit()`
fails. Default `CircuitOptions` (3-minute disconnected retention), no `PersistentComponentState`, no
`#blazor-error-ui`. A player who locks their phone for four minutes mid-journal-entry comes back to an empty
editor and no message. The `UnsavedChangesGuard` cannot fire on a reload the app triggers. Fix: mirror editor
drafts to `sessionStorage` keyed by field and restore on load; raise `DisconnectedCircuitRetentionPeriod`;
replace the blind reload with a recovery view.

**D10. World builder apply: three holes in the "nothing is written twice" story (P1).**
- `PlacesAsync` (`WorldBuilderService.cs:1066-1163`) persists region by region and *returns* the list;
  `SavedAs["place"]` is recorded afterwards (`:783-786`). A failure saving region B after region A's places
  were upserted leaves no `SavedAs`; the UI says "Apply again to save the rest" and A's places are created
  twice. Pages/homebrew/cast record per entity, places do not.
- Two tabs clicking Apply inside the window between the guard save and the first per-entity save both pass
  the version check and both create everything up to the loser's first per-entity save (`WorldChat.cs:573-
  585`). The `AppliedEpoch` marker remediation 2.1 asked for was not built.
- `get_page` truncates the *expanded* text (`Editable(body, names)`, mentions as `[[actor:id|Name]]`) at
  6,000 chars (`:170-171`), while `TooLong` (`:447-452`) refuses an edit only when the *raw* body exceeds
  6,000. A 5,900-char body with twenty mentions is read truncated, rewritten "complete", passes the check,
  and the tail is lost on apply unless it held a `:::dm` block.
Fix: `Saved(draft, "place", id)` inside `PlacesAsync`; an `Applying = epoch` field in the guard save (or a
compare-exchange lock); measure the same string in both places.

**D11. Backups do not exist, and the app knows it (P1).** `Program.cs:516-525` schedules a RavenDB periodic
backup and catches the failure with "continuing without it"; `packaging/smoke-test.*` whitelist the
`LicenseLimitException` in that log line; the README admits the free licence forbids it; the launcher has a
"Backups folder" button (`LauncherViewModel.cs:417-421`) that silently opens the data folder when `Backups/`
does not exist. Users, accounts and AI providers have no backup path at all (campaign export covers
campaigns only, with no images, see D13). Fix: detect the licence refusal at startup and show "backups: off"
in About/launcher; fall back to a scheduled JSON export of every campaign into `Backups/` with retention.

**D12. Data Protection keys live outside the data folder (P1).** `Program.cs:158` `AddDataProtection()` with
no `PersistKeysToFileSystem`/`SetApplicationName`: keys go to `%LOCALAPPDATA%\ASP.NET\DataProtection-Keys`
or `~/.aspnet/…`, not `dataHome`, contradicting the README ("under the server's data directory"). Moving or
restoring the data folder, or running under another OS user, loses every stored AI key (handled gracefully at
`AiProviderService.cs:85-102`, but silently) and invalidates every cookie; an unwritable profile dir makes
the keyring ephemeral and logs everyone out on each restart. One purpose string for all users
(`"Codex.AiProviderKeys.v1"`), so a blob copied between users decrypts. On Linux the ring is plaintext XML.
Fix: `PersistKeysToFileSystem(Path.Combine(dataHome, "Keys")).SetApplicationName("TTRPG.Codex")`; chain
the purpose with the user id; keep the folder out of exports; say the Linux at-rest caveat.

**D13. Export/import does not do what the copy says (P1).** `CampaignExportService.cs:95-121`: "Restore as
new" never remaps ids, so if the bundled campaign id still exists and the user is its DM the import
*overwrites* it; import is upsert-only, so documents deleted after the export survive while the hint promises
a restore; `InviteCode` is exported (anyone holding the file can join); only actor `Sheet/State` and homebrew
`Properties` are normalised from `JsonElement` (`:196-203`) while `campaign.WorldState`, `fact.Metadata`,
`location.Metadata` and `encounter.ActiveEffects` are persisted as what the code's own comment calls
"garbage" (a pack place's `Metadata["blueprintId"]` never matches again); images never travel. Fix: remap ids
when restoring as new; strip `InviteCode`; normalise every map; say "merge" and "without images".

**D14. Invite codes are 32 bits, never expire, and the limiter does not see in-app joins (P1).**
`Guid.NewGuid().ToString("N")[..8]` (`CampaignRepository.cs:101`, `SettingsSection.razor:336`). The rate
limiter keys on the HTTP path `/campaigns/join` (`ExposurePolicy.cs:19-20`), but `JoinCampaign.razor` is an
interactive page: once anyone has an account on an exposed server, navigating inside the app to
`/campaigns/join/{guess}` runs `JoinByInviteCodeAsync` over the circuit with no counted request. The code is
also the only gate for account creation on an exposed server. Fix: 128-bit codes from
`RandomNumberGenerator`, optional expiry/one-shot, a per-user attempt counter inside the join method.

**D15. Authorization is resolved once per page load; the campaign write API takes no access (P1).**
`CampaignPage.razor:284` resolves `access` only when `CampaignId` changes. Sections then call
`ICampaignRepository.UpdateAsync(id, mutate)` (`SettingsSection.razor:282,303,311,323,337,360-365`),
`IMediaStore.PutAsync` and `INoteRepository.DeleteNoteAsync(id)`, none of which take a `CampaignAccess`. A
demoted or removed co-DM keeps DM powers (roles, invite regeneration, member removal, cover) on their open
circuit until they navigate away. Fix: pass `CampaignAccess` into these methods and re-resolve inside (the
pattern `TrySaveAsync` already uses).

**D16. A player's history save flattens revealed blocks (P1, remediation 2.6 half-landed).**
`SecretText.KeepSecrets` (`SecretText.cs:337-352`) keeps only what the player cannot read and runs
`ForPlayers` over the rest: a spelling fix turns a `:::party <timestamp> …` block into plain prose, losing
the "revealed" marker, the stamp, and the DM's ability to hide it again, and moves DM blocks to the end.
Refuse-on-conflict did land (`RavenActorRepository.cs:217-242`). Fix: preserve stored Party/Players blocks
with their opener lines, matched by inner text as `LostSecrets` does.

**D17. Deleting an actor degrades every mention of them to "someone", for the DM too, with no warning
(P1).** `MentionDirectory.Read` (`SessionMentions.cs:169-171`) returns `UnknownActor` for any id not in the
live actor list; `Campaign.Cast.DeleteBody` says only "Their sheet and state are removed". Notes, recaps,
pages, facts, journals lose the name; `:::for [[actor:x]]` blocks become readable by nobody; `KnownBy` shows
"?"; `WikiPageDocument.ActorId` dangles so "Promote to cast" reappears. Unrecoverable. Deleting a wiki page
likewise orphans its notes and dangling `WikiPageId`s. Fix: soft-delete (retired flag the directory still
names), or at least count mentions in the confirm dialog.

**D18. Users are last-writer-wins (P2 edging P1).** `RavenUserRepository.cs:40-45` stores the whole
document; callers include `/set-culture`, the login rehash, AI settings and external-login linking. Saving a
provider in one tab while switching language in another drops the provider and its key. Fix:
`RavenUpdate.RunAsync<UserDocument>`.

## 3. Wrong rules, edge cases and runtime robustness (P1/P2)

**R1. Quick-added monsters are Hidden and the table has no reveal (P1).** `CombatConsole.razor:1047-1057`
sets `Hidden`; the only reveal controls live in Cast and Bestiary. "Search goblin → Add → roll → fight" gives
players an order with no goblins and "Someone you can't see" on every monster turn; the DM leaves the table
per monster to fix it. Fix: a per-row visibility toggle in the DM panel; default quick-add to `Unknown`.

**R2. Removing the current-turn participant hands the turn over without beginning it or skipping the
dead (P2).** `CampaignRuntime.cs:245-278`: `TurnIndex` moves but `BeginTurn` is not called and the dead-skip of
`NextTurnCommand` (`RuntimeCommands.cs:431-436`) is not applied. "Remove from order" is used precisely on
dead or fled creatures, often on their own turn. Fix: extract and reuse the advance routine.

**R3. "Mark dead"/"Revive" bypass `TableRules` (P2).** `CombatConsole.razor:875,857` add/remove the "Dead"
condition directly; `TableRules.Die` (`:474-488`) also clears Down/Stable and the death-save tally. A revived
PC comes back Unconscious with 2/3 failures and dies on the next hit. No confirm on Mark dead (flagged in the
October review, still open). Fix: `KillCommand`/`ReviveCommand` on `TableRules`.

**R4. Effects anchored to a dead or removed actor never expire; no concentration (P2).** `AdvanceTurn` ticks
only on the anchor's own turn boundary; dead participants are skipped and removed ones dropped, so Bless from
a dead cleric lasts until "End encounter". `grep oncentrat` finds nothing in the runtime: the most common 5e
bookkeeping is manual and undiscoverable. Fix: expire anchored timed effects on death/removal; an optional
`Concentration` marker with a prompt on damage.

**R5. No undo for a mistyped damage number (P2).** `PreviousTurnCommand` exists; nothing for
damage/heal/temp HP/condition (`RuntimeCommands.cs:12-121`). 21 instead of 12 means hand-healing 9, a wrong
log line, and cleaning up `Unconscious` plus death-save state by hand. Fix: `UndoLastCommand` per actor
(capture pool + effects before `Apply`), surfaced as an undo toast.

**R6. Runtime lifecycle races (P2).**
- `CampaignRuntimeManager.cs:93-105` publishes the runtime via `TryAdd` *before* `InitializePlugins` and
  `Hydrate` run; `TryGet` already returns it, so a command can iterate `_actorEntities` while `HydrateOne`
  adds to it. If `Hydrate` throws, the half-built runtime stays cached and `RuntimeChanged` never fires.
- Double "Start table": `OpenSessionAsync` creates and saves a session and patches `CurrentSessionId` before
  `TryAdd` (`:60-109`); the loser is disposed but its session document and the double patch remain. The
  start button does not use `CodexButton.Busy`.
- Dispose (`CampaignRuntime.cs:688-703`) cancels the channel without draining it: a queued roll or
  `TrySaveActorAsync` awaits forever (sheet save spinner never ends) when the table is ended underneath it.
- Idle eviction (2 h, `IdleRuntimeEvictionService.cs:12`) counts only `EnqueueAsync` as activity, so a long
  roleplay stretch with four circuits watching evicts the table under them.
Fix: hydrate before `TryAdd` and remove on failure; a per-campaign `Lazy<Task<CampaignRuntime>>`; drain and
fault queued completions on dispose; count subscribers as activity.

**R7. Rules engine edges (P2).**
- Multiclass prepared-spell limit is pooled (`SheetRuleEngine.cs:997-1009`): Cleric 1 / Wizard 5 can
  prepare 13 wizard spells.
- Level-up has no upper bound (`ActorSheet.razor:1685-1706` writes 21, 22…; PB becomes +7; tables use the
  level-20 row silently).
- A pick whose Library entry was removed renders no chip, so it cannot be removed (`SheetRuleEngine.cs:195-
  201`, `EntryListPicker`); a strict-mode player is locked out of saving with nothing to click. The
  multiclass list handles this correctly (`:497`).
- Formula errors are *violations* a player cannot fix (`EvaluateDerived :795-804`), and `Derived[pb]` goes
  missing so every skill silently loses PB; `10/(level-level)` casts ∞ to `long.MinValue` without error
  (`:808-809`); derived formulas cannot reference other derived keys.
- Homebrew class without `hitDie` or `spellcasting` fails silently (`Vitals.cs:132-136`; `ResolveCount` reads
  "no table" as 0).
- `SchemaForm.razor:298-305`: non-numeric input silently resets the field to default; `1e20` into an
  unbounded number wraps to `long.MinValue`; `ArmorClassPanel.razor:195` writes 0 for any non-numeric.
- A removed `class`/`species`/`background` entry shows "None" in the select while the sheet still holds the
  id (`SchemaForm.OptionsFor :269-289` appends the stale option only for constrained fields).
- A new attribute added to `system.yaml` never reaches existing sheets (`ApplyAttributeTotals :437-444`
  skips attributes without `base_`); a renamed one resets to Default and leaves dead data.
- Class skill-choice count is free text and unenforced (`system.yaml:306`; `SkillsPanel` lets a player tick
  all 18); equipment weight is never summed.
- Homebrew formulas run on `new Interpreter()` with the default surface (`SheetRuleEngine.cs:814`), parsed on
  every render of every viewer: `new string('a', 1_000_000_000)` in an imported pack is a trivial DoS, and raw
  `ex.Message` is shown to players. `ScriptEvaluator.cs:65` already caches a `Lambda`; the engine should too,
  with `InterpreterOptions.None` plus the five functions it needs.

**R8. Dice grammar (P2).** One dice term and one modifier only (`DiceExpressionParser.cs:22-24`): `1d8+1d6`
(sneak attack), `2d6+3+2`, `1d20+5-2` all fail. `DiceResult.razor:168-169` marks a crit when
`Expression.Contains("d20")`, so `1d200` rolling 20 is a natural 20. `ActorSheet.razor:962` rolls on
`StandardDiceRoller.Instance`, bypassing the system plugin's roller the table uses.

**R9. Max-key convention is inconsistent (P2).** `TableRules.cs:21-22,69` resolve `resource.maxKey` from the
system; `CodexWorld.ApplyHealing/AdjustResource/RestoreResources` (`CodexWorld.cs:185,208,223`),
`HitDiceRules.MaxKey`, `AdjustExhaustion` and `CombatConsole.razor:357` hard-code `_Max`/`HP_Max`. A
homebrew `{ key: Wounds, maxKey: WoundCap }` gets damage clamped but healing unbounded and a `x/0` display.
`CodexWorld.ApplyDamage` (`:140-173`) hard-codes "HP"/"TempHP" and has no callers.

**R10. Session dates use the server's time zone and cannot be edited (P2).** `SessionsSection.razor:113`
`SpecifyKind(newDate, Local).ToUniversalTime()` in Blazor Server is the *server's* zone; display is the
viewer's (`LocalTime`/`ViewerClock`). A UTC container and a UTC-5 DM: "Nov 1" shows as "Sat 31 Oct, 19:00",
and `SessionDetail.SaveDetailsAsync` (`:400-410`) saves only title and status.

**R11. Renaming a wiki page breaks backlinks, counts and "Lore about" (P2).** `Links` are stored as
`Slugify(linkText)` (`WikiModels.cs:233`) while rendering resolves by slug *or* title (`WikiRender.cs:22-24`)
and the slug never follows a rename (`:239-242`). `[[Castle Greyharbour]]` renders but is invisible to
"Links here", dropped from a player's `Links`, and `FactLinks.Of` stores `wiki:castle-greyharbour` while
`LoreAbout` asks for `wiki:the-keep`.

**R12. Cascade delete still reads stale indexes (P2, prior F15 partly fixed).** `RavenActorRepository.cs:276-
278`, `RavenSessionRepository.cs:36-38` and the note/region/fact/homebrew/encounter/template
`DeleteAllForCampaignAsync` lack `WaitForNonStaleResults`; only Journal, Wiki and WorldChat got it. Orphans
resurrect on a later import under the same id.

**R13. Server hardening left open (P2).** No login throttling except behind Funnel (`Login.razor:127-168`),
and LAN mode binds plain HTTP, so a guest brute-forces unencrypted credentials without limit. First-account-
becomes-admin is check-then-create (`Register.razor:149-155`) and the launcher's "Host" flow turns LAN on and
opens the browser before the DM has an account (`App.axaml.cs:153-169`): the first LAN player to register is
ServerAdmin. `Login.razor:108` reflects any `?error=` text inside the app's own alert (encoded, but a phishing
line on a public Funnel URL). Every `*.dll` under the DM's "My content" folder is `Assembly.LoadFrom`'d
(`PluginLoader.cs:289-293`; the launcher opens that folder for the DM) with no trust statement in the docs.
Content-pack YAML errors are logged and swallowed (`YamlContentPackLoader.cs:474-510`); `PluginLoader.Warn`
has no callers and `LoadException` no reader, so entries vanish from the Library with nothing on screen. The
server-wide AI key is spendable by every account on a LAN server with no budget and no attribution
(`AiProviderService.cs:34,138`); the settings page does not say so. `JsonReplyAsync` (`AiAssistant.cs:60-
73`) retries *every* failure without `response_format`, including 401/429, doubling the cost of error paths.

**R14. World-chat housekeeping (P2/P3).** Context overflow is detected and offered a "carry on in a new
chat" recap, but the old chat is dead forever (only tool results are trimmed, `WorldChat.cs:435-465`; no
token budget). `SaysNoTools` classifies on `ex.ToString()` with the words "tool" and "support" (`:699-701`),
so any `NotSupportedException` through a frame named `*Tool*` tells the DM to change models. Prompt says "at
most 8 entries", schema says 30. `propose_changes` error text embeds campaign-controlled names unfenced
(`:454-460`), the one seam the fence was built for. No undo of an applied proposal; wiki pages have no
revision history. `Ctx.ReloadAsync()` after apply runs only for actors/places/shortlist
(`WorldChatSection.razor:675`), so edited pages look stale. The chat document holds up to four copies of each
proposal and full tool results and is rewritten whole on every save.

## 4. UX against the Owlcat yardstick

The October review (docs/ui-review.md) is honest about what landed. Verified: B1–B10 and phone items 1–9
are fixed; the markdown editor (toolbar, preview, full-screen, `@#$` and `[[` autocomplete, templates,
Ctrl+S) is good work. Verified *not* landed: P1 peek cards (partial), P2 window routes (none), the C/I/J/L/N
shortcuts (none), B5 (partial), and section 4's unconfirmed destructive actions (still open outside the wiki).

**U1. There is no encyclopedia, only a desktop tooltip.** The hover card (`app-startup.js` final IIFE,
`PreviewEndpoints.cs`) is gated on `matchMedia("(hover: hover)")`, so the device players actually hold gets
nothing; it has `pointer-events: none` (`app.css:2291`) and hides on any click, so it cannot be pinned,
clicked into, or chained; it resolves actors, pages and places only: no Library entries, conditions, sessions
or roll results. The live table still has zero links. Condition rules, effect expiry and initiative
explanations live in `title=`, which phones never show (the tap-tip excludes `button` targets, so the six
icon-only editor toolbar buttons are unexplained on a phone).

**U2. Big screens are pages, not windows.** `ActorSheet.razor` and `SessionDetail.razor` are separate
`@page` routes outside `CampaignPage`: opening a character from the table loses the bottom tab bar and the
notes drawer (`TableNotesHost` is mounted only at `CampaignPage.razor:165`, contradicting its own header
comment), returning re-creates the page (skeleton, scroll lost), "Back to cast" goes to Cast even when you
came from the Table, and place links land on a collapsed `<details>` (`WorldSection.razor:89`). The phone
`.phone-sheet` sits above the tab bar with a single exit and no Escape.

**U3. Nothing has undo, and several irreversible actions have no confirmation.** Art removal (`ArtSlot.razor:
180` via Library and Settings), AI provider removal (`AiSettings.razor:334`), invite regeneration
(`SettingsSection.razor:334`), role change on `<select>` change (`:308`, a mis-scroll on a phone select
promotes someone to DM), fact "Forget" (`LoreSection.razor:464`), schema row removal, "Mark dead". Wiki
"Expand with AI" and sheet "Rewrite" overwrite the editor with no `previous` (`WikiSection.razor:1160`,
`ActorSheet.razor:1630`) while `AiTextField` keeps one. No applied-proposal revert. The only "Undo" string in
the app is `Library.Ai.Undo`.

**U4. Level-up is "edit the number and good luck".** `ApplyLevelUp` sets `level+1` and flashes "Update hit
points and features, then Save". The consequences are scattered across tabs: feat slot on Picks, ASI points
on Attributes (the violation text is the only guide), subclass in the Sheet form at level 3, HP roll inside a
`<details>`. The class `features` rows hold exactly the data a stepper needs. Errors are not shown next to
the field: everything but attribute boxes reports into one panel on the Attributes tab, so a player over the
feat limit on the Picks tab sees a red count pill and the reason elsewhere. Skills, saves, initiative and PB
have no breakdown (`SkillsPanel.razor:66` shows `+7`), though AC, HP and attributes do and the engine has
every term.

**U5. Feedback lands where you are not looking.** `Ctx.Notify` renders a banner at the top of `.ws-main`
that is cleared only when the campaign id changes (`CampaignPage.razor:117,261-266`): "Saved." from Settings
is still there when you open Table later; on a phone the Lore form sits below the list so "Fact saved."
appears off-screen. Settings and AI settings report *validation* errors through that banner instead of inline.
Silent no-ops on bad combat input (negative or blank amount, empty manual initiative inserting at 0, "0 rounds
means until removed" only in `title=`).

**U6. One save model per page.** Session detail has four Save buttons (`SessionDetail.razor:84,103,134,208`)
sharing one `SaveGate`, so Ctrl+S on the recap is dropped while the journal saves; Settings has two forms plus
on-select roles and instant cover; Bestiary autosaves; World saves art immediately but name/description on
Save, then asks "discard changes" though the art is already permanent; the fact editor is a bare textarea with
no preview, no secret button and no leave guard. Twelve distinct "Save …" labels and six "… saved." strings.
Double-submit is unguarded in `CastSection.CreateAsync`, `LoreSection.CreateAsync`, `SettingsSection`
saves, `AiSettings.SaveAsync` and `LibrarySection.AddToCastAsync` (two taps, two actors).

**U7. Phone tab bar is role-blind.** `CampaignPage.razor:203` fixes Table, Sessions, Journal, Places for
everyone; a DM reaches Cast, Bestiary and Wiki only through More. Library type chips push a history entry per
tap and the query is not in the URL (`LibraryBrowser.razor:285`). No place, region or session can be
deleted at all. `offline.html` follows `navigator.language`, not the app's culture cookie.

**U8. Terminology drift.** "Places" / `world` / "World" / "regions" / "map" for one screen; "Remove this
note" / "Delete note" / "Delete entry" for one act; "Table running" / "no session running" / "Join table".
Seven places to write prose, each with its own verb and its own secret-syntax support.
