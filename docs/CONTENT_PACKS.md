# Systems and content packs

Everything a game needs - attributes, the character sheet, classes, spells, monsters, places, lore -
is data. TTRPG.Codex loads it from **content roots** at startup:

- `plugins/` and `content/` next to the published executable (what a release ships), and
- the folders listed under `Codex:ContentDirectories` in `appsettings.json` (the repo's `content/`
  by default when running from source).

Inside a content root the layout is free-form; the loader looks for three kinds of thing anywhere
below it (skipping `bin/`, `obj/` and dot-folders):

| Thing | Marker | What it is |
|---|---|---|
| **System** | `system.yaml` | A game system: attributes, resources, sheet fields, content types, conditions, dice. |
| **Pack** | `manifest.yaml` (or legacy `manifest.json`), or a `.zip`/`.cdx` archive | Content for one system: rules, a setting, or homebrew. |
| **Compiled plugin** | `*.dll` directly in the root | An `ICodexSystemPlugin` for behaviour data can't express (custom dice, ECS systems). |

The shipped tree:

```
content/
  systems/srd5e/
    system.yaml                 Fifth Edition SRD (5.2.1) - the system definition
    packs/srd-5.2.1/            the SRD content, generated by tools/Codex.ContentImport
      manifest.yaml  LEGAL.md  classes/  spells/  monsters/  feats/  species/  ...
  examples/
    simple-d6/                  a tiny homebrew system (system.yaml + packs/core)
    homebrew-world/             a setting pack for srd5e: lore, locations, NPCs
```

## system.yaml

```yaml
id: simple-d6                 # lower-case, stable; campaigns reference it
name: Simple d6               # shown in the UI
version: 1.0.0
compatibility: 5E compatible  # optional: the only product reference the UI shows
description: ...
license:                      # shown on the About page and under every entry
  name: CC-BY-4.0
  url: https://creativecommons.org/licenses/by/4.0/legalcode
  attribution: "This work includes material from ..."   # verbatim, if the licence requires one
  sourceUrl: https://...
  modified: true              # CC-BY: say so if you changed the material
  notices: [ "..." ]          # extra notices (upstream MIT, trademark disclaimers)

attributes:                   # per-actor scores; modifier: none | half-minus-five (the d20 rule)
  - { key: str, label: Strength, abbreviation: STR, default: 10, min: 1, max: 30, modifier: half-minus-five }

resources:                    # depletable pools; the primary one is what damage/healing target
  - { key: HP, label: Hit Points, maxKey: HP_Max, default: 10, isPrimary: true }
  - { key: TempHP, label: Temporary Hit Points }

actorFields:                  # the rest of the sheet; same field schema as content types
  - { key: level, label: Level, type: Number, defaultValue: 1 }
  - { key: class, label: Class, type: EntityReference, targetEntityType: class }   # picker from the Library

conditions: [Blinded, Charmed, ...]   # offered in the table's condition picker
dice: { initiative: 1d20, check: 1d20 }

entityTypes:                  # what packs for this system may contain
  - type: spell               # singular key; the Library groups by it
    label: Spell
    pluralLabel: Spells
    folder: spells            # pack folder (defaults to the type key)
    icon: flame
    summaryFields: [level, school]      # shown in list rows
    filterFields: [level, school]       # (reserved for facet filters)
    playerFacing: true                  # false hides the type from players' pickers (monsters)
    fields:
      - { key: level, label: Level, type: Number }
      - { key: school, label: School, type: Dropdown, options: [Abjuration, ...] }
      - { key: concentration, label: Concentration, type: Boolean }
      - { key: classes, label: Classes, type: TagList }
      - { key: features, label: Features, type: Collection }   # rows of {level?, name, description}
  - type: monster
    actorBlueprint: true                # entries double as creatures the DM can add to the cast
    hitPointsProperty: hitPoints        # which property seeds the primary resource
    attributeProperties: { strength: str, dexterity: dex }   # property -> attribute key
```

Field types: `Text`, `LongText`, `Number` (honours `min`/`max`), `Boolean`, `Dropdown` (`options`),
`TagList` (comma-separated), `EntityReference` (`targetEntityType`), `Collection` (rows), `ImagePicker`.

### Sheet rules (`sheetRules`)

What a character sheet may contain is data too, so a homebrew can be as strict or as loose as it
likes. Leave `sheetRules` out and anything goes. The SRD system uses every kind of rule:

```yaml
sheetRules:
  enforcement: strict          # strict: players can't save a sheet that breaks a rule (the DM always can)
                               # warn: show problems but allow saving; off: don't check.
                               # A campaign can override this under Settings > House rules.
  attributes:
    methods: [point-buy, standard-array]      # what players may pick; the DM also gets "manual"
    default: point-buy
    max: 20                                   # cap on base + bonuses
    pointBuy: { budget: 27, min: 8, max: 15, costs: { 8: 0, 9: 1, 10: 2, 11: 3, 12: 4, 13: 5, 14: 7, 15: 9 } }
    standardArray: [15, 14, 13, 12, 10, 8]
    bonuses:                                  # bonuses granted by a referenced entry
      label: Background bonuses
      fromField: background                   # the sheet field that references the entry
      property: abilityScores                 # that entry's list of eligible attributes (keys, abbreviations or labels)
      allocations: [[2, 1], [1, 1, 1]]        # allowed spreads, one bonus per distinct attribute
  derived:                                    # read-only, computed from numeric sheet fields
    - { key: proficiencyBonus, label: Proficiency Bonus, formula: "2 + (level - 1) / 4" }
    #  floor(), ceil(), max(), min() and mod(score) (the half-minus-five modifier) are available
  constraints:                                # on single-pick reference fields
    - field: subclass
      where:
        - { property: class, equalsField: class, message: "that subclass belongs to another class." }
    - field: originFeat
      where:
        - { property: category, equals: origin }
        - { property: id, equalsPropertyOfField: { field: background, property: feat } }
  lists:                                      # multi-pick lists shown under "Picks" on the sheet
    - key: spells
      label: Prepared spells
      targetEntityType: spell
      where:
        - { property: level, gte: 1 }
        - { property: classes, containsNameOfField: class }       # the spell's class list names the sheet's class
        - { property: level, lteLookup: { field: class, table: spellcasting, byField: level, column: maxSpellLevel } }
      maxCount: { lookup: { field: class, table: spellcasting, byField: level, column: preparedSpells } }
```

Conditions compare a property of the candidate entry (`level`, `classes`, `category`, or `id`,
`name`, `tags`) with a constant (`equals`, `in`, `gte`, `lte`), a sheet field (`equalsField`,
`lteField`, `gteField`), the entry another field references (`containsNameOfField`,
`equalsPropertyOfField`) or a value looked up in that entry's row table (`lteLookup`). A lookup
takes the row whose `level` (or `rowKey`) is the highest not above the sheet's `byField`. A
`maxCount` that looks up a table the chosen entry doesn't have is zero (a fighter's spells); with
nothing chosen yet it is unlimited.

Base scores live in the sheet as `base_<key>` and bonuses as `bonus_<key>`; the engine writes the
total into `<key>`, which is what the live table and the ECS use. List picks are stored as lists of
entry ids under the list's key.

Validation runs at load. A broken `system.yaml` is reported on the About page under "Content
warnings" and the system is skipped; nothing else stops loading.

## manifest.yaml

```yaml
id: srd-5.2.1                 # unique across all packs
name: System Reference Document 5.2.1
version: 5.2.1
systemId: srd5e               # the system this pack belongs to
kind: rules                   # rules | world | homebrew (informational)
priority: 0                   # higher wins when two packs define the same entry id
dependencies: [other-pack]    # loaded first, so `inherits` can resolve
description: ...
authors: [ ... ]
license: { ...as above... }
```

## Entries

Each file under a type folder holds one entry or a list of entries:

```yaml
- id: fireball                # stable within the type
  name: Fireball
  description: |              # Markdown subset: **bold**, *italic*, "- " bullets, | tables |, ### headings
    *Level 3 Evocation*
    ...
  tags: [evocation, level-3]
  inherits: fire-bolt         # optional: id (same type), type:id, or system:type:id
  properties:                 # the type's fields; numbers and booleans are typed automatically
    level: 3
    school: Evocation
    classes: [Sorcerer, Wizard]
```

Three legacy folders keep their older, richer shapes: `abilities/` (executable TRCE abilities),
`actors/` (NPC blueprints with `resources` and `properties`), `locations/` (places with
`parentId` and `connections`). Setting packs use `actors/` and `locations/` for their people and
places, and a `lore` entity type for everything else.

## Homebrew without files

A DM creates homebrew in the campaign's **Library** section. Entries use the same field schema as
the system's content types, are searchable alongside pack content, can be hidden from players while
drafting, travel with the campaign export, and can be exported as a pack (zip) with **Export
homebrew pack** - drop the zip into a content root to share it with another server.

## Importing the SRD

The SRD pack is generated, not hand-written:

```bash
dotnet run --project tools/Codex.ContentImport -- srd5e --download --source /tmp/srd-json --out content/systems/srd5e/packs/srd-5.2.1
```

`--download` fetches the 5e-bits JSON transcription from a pinned commit (see
`tools/Codex.ContentImport/SrdDownloader.cs`). The manifest it writes carries the verbatim SRD 5.2.1
attribution statement, the modification notice CC-BY-4.0 requires, and the 5e-bits MIT notice.
`tests/Codex.Tests/SrdPackSmokeTests.cs` checks the generated pack against the document's counts.
